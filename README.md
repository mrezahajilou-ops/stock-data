# stock-data — nightly SEC fundamentals for rezahajiloubooks.com
- `scripts/build.py` downloads SEC EDGAR bulk XBRL data and writes one JSON per US-listed stock into `data/stocks/`.
- `scripts/verify.py` checks a sample of companies against independently published figures.
- `.github/workflows/nightly.yml` runs it every night and commits the result.
Data: U.S. SEC EDGAR (public domain). Prices are not included.

## Persian site (Shopify): adding a tool page without touching the theme

The theme has one generic template, `templates/page.app.liquid` (added 20 Nov 2026). A new tool needs:

1. `web/<app>.html` committed here (build it in `gen_web.py`);
2. a Shopify page with handle `<app>` and template suffix `app` (Admin API `pageCreate`);
3. the text search engines should read in that page's own body (`pageUpdate`), not in the theme.

Optional page metafields: `rz.app` (app name if it differs from the handle), `rz.ld` (extra JSON-LD),
`rz.noad` (`1` hides the ad). Publishing a theme is only needed for changes to the theme's own chrome.
The connector cannot publish themes on this store, and the store is at its 20-theme limit, so
`themeDuplicate` silently returns nothing; edit an existing draft instead.

## Earnings analyses and big movers (written content)

Two kinds of hand-written notes sit on top of the automatic data. Both are written in a chat session from primary
documents, never generated by a job, and both are shown by every site from the files under `data/`.

**Earnings analyses** (500 largest companies, after each report)
- `earnings_pr.py` + workflow *Earnings releases* (hourly on weekdays) → branch `earnings-pr`: `recent.json` (who reported
  in the last 12 days) and `pr/<T>.json` (the text of the company's own release from its 8-K / 6-K).
- Read a release with `python3 tools/release_show.py "TICKER:chars:regex"` (expects the branch cloned to `/tmp/epr` and the
  `earnings` branch to `/tmp/earn`).
- Write with `tools/earnings_note.py`: `note(t, d, q, headline, takeaway, results, mgmt, view, watch)` saves
  `content/earnings_en/<T>/<d>.json`; `compile_notes()` builds `data/earnings_notes/en/<T>.json` and `index.json`.
- Shown: stock tool page (`web/stock.html`, the latest-earnings card next to the super-investors card; language from
  `window.RZS_LANG`), the earnings calendar (`web/calendar.html`, an "analysis" link on the row), and on the English site
  the report's own article `/news/<t>-earnings-<yyyy-mm>/`, the stock page and the earnings tab (`tools/notes_en.py`).
- Rules: every figure comes from the release; say when a headline number includes a one-off (tariff refunds, an extra
  week); four parts — results, what management said, our analysis (3+ paragraphs), what to watch.

**Big movers** (companies worth $2B+ that closed ±10%)
- `PRICES_DIR=/tmp/prices EARN_DIR=/tmp/earn python3 movers.py YYYY-MM-DD` lists the day's movers from the `prices` branch
  and writes `data/movers/raw/<date>.json`.
- Workflow *Big movers - what the company filed that day* (`movers-facts.yml`, inputs `day`, `tickers`) → branch
  `movers-facts`: `mv/<date>/<T>.json` with the 8-K / 6-K filings of the day and the three days before.
- Write with `tools/mover_note.py`: `day(d)`, `mv(t, headline, summary, why, context, src, kind)`, `compile_movers()` →
  `content/movers_en/<date>/<T>.json`, `data/movers/en/<T>.json`, `days/<date>.json`, `index.json`.
- Shown: the "what happened" card on the stock tool page for 15 days, and on the English site an article
  `/news/<t>-stock-move-<date>/`, a card on the stock page and the "Why they moved" block of `/stock-market-today/`
  (`tools/movers_en.py`).
- Rule: a move is published only when its cause is confirmed from a filing or a reliable report. No guesses; a mover
  without a confirmed cause is left out.
